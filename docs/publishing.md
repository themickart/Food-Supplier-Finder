# Подготовка GitHub и GitHub Pages

Исходники публикуются в `themickart/Food-Supplier-Finder`, ветка `main`. Собранная автономная версия — в отдельную ветку `gh-pages`, которая служит источником GitHub Pages.

## Что исключено

`.gitignore` оставляет локальными:

- `Task.md` (без учёта регистра имени) и `docs/task-audit.md`, который подробно пересказывает задание.
- `.env`, `.env.*`, файлы ключей/учётных данных, локальные настройки агентов, редакторов и облачных CLI.
- `data/`, БД SQLite и их служебные файлы, резервные копии, выгрузки CSV/XLSX, архивы.
- `.venv/`, `node_modules/`, браузеры Playwright, кеши, логи, скриншоты, трассировки и отчёты тестов.
- `dist/`, `dist-pages/` и другие результаты сборки: GitHub Actions собирает их из исходников.

Файлы не удаляются с компьютера. Задание исключено до первого коммита исходников и в публикуемую Git-историю не включается. Проверка перед публикацией также отклоняет исключённые файлы, если они были принудительно добавлены в индекс.

Публикуются исходники frontend/backend, тесты и миграции, Docker-конфигурация, инструкции по запуску/архитектуре/источникам/ограничениям, `package-lock.json` и `requirements.lock.txt`. Учебный JSON-набор намеренно доступен посетителям и содержит только явно вымышленные компании с `.example`-источниками.

Исключения для конфигурации: `.env.example` и шаблоны `.env.*.example`; `frontend/.env.pages` содержит только два публичных параметра сборки, без ключей. Настройки приватных провайдеров туда не добавлять.

`.dockerignore` исключает эти же локальные материалы из контекста Docker. `.gitattributes` задаёт LF для текстовых файлов и дополнительно исключает задание/внутреннюю сверку из `git archive`.

## Проверка состава исходников

Из корня, Node.js 22.12+:

```powershell
node scripts/check-publication.mjs
Set-Location frontend
npm.cmd ci
npm.cmd test
npm.cmd run build:pages
npm.cmd run check:publication -- --pages-dir frontend/dist-pages
Set-Location ..
git status --short
```

Скрипт проверяет фактический список отслеживаемых и новых файлов, правила исключения, отсутствие исключённых файлов в индексе, типовые приватные ключи/токены без вывода их значений, относительные ссылки документации, публичную конфигурацию и учебный набор. Проверка артефакта допускает только статические ресурсы Pages; ТЗ, БД, исходные `.py`/`.ts`, source maps и секретные файлы в артефакте отклоняются. Это проверка текущих правил и известных форматов, не универсальное распознавание любого возможного секрета.

Для просмотра того, почему исключено задание:

```powershell
git check-ignore -v Task.md docs/task-audit.md
```

После успешных проверок команды публикации исходных изменений:

```powershell
git add .
git diff --cached --stat
node scripts/check-publication.mjs
git commit -m "Prepare FSUP supplier workspace prototype"
git push -u origin main
node scripts/publish-pages.mjs --push
```

`git add .` учитывает `.gitignore`; не использовать принудительное добавление локальных материалов. В GitHub Desktop перед Commit/Publish аналогично проверить список файлов: `Task.md` и внутренняя сверка должны отсутствовать.

## GitHub Pages

[Подробная инструкция](github-pages.md). В Settings → Pages выбрать **Deploy from a branch → gh-pages → / (root)**. Сайт публикуется по адресу `https://themickart.github.io/Food-Supplier-Finder/` после успешного выполнения Pages build.

Скрипт `scripts/publish-pages.mjs --push` запускается из чистой `main`: проверяет исходники, собирает/проверяет Pages и публикует отдельный снимок в `gh-pages` обычным push без переписывания истории. Ветка содержит только статические ресурсы, `.nojekyll`, README показа и metadata с исходным коммитом. Checkout `main` не меняется. Без `--push` удалённая ветка не обновляется.

Workflow **Check Pages build** проверяет `main` на push и при ручном запуске: исходники, модульные тесты, статическую сборку и browser E2E. Он сохраняет артефакт в Actions; ветку сайта самостоятельно не обновляет. После изменений приложения обновляйте и `main`, и `gh-pages` по командам выше.

Pages показывает автономный прототип: каталог и личные данные сохраняются в браузере. Серверная БД, внешний поиск и ИИ в этой публикации не появляются. Старый бренд пока сохранён согласно решению пользователя.
