# Развёртывание, резервные копии и исправление данных

## GitHub Pages

Для текущего бесплатного показа подготовлена отдельная автономная сборка. [Инструкция, ограничения хранения и ручной workflow](github-pages.md). Сервер Python/PostgreSQL в Pages не запускается; общий каталог заменён браузерным только для этой демонстрации. Публикуется собранная ветка `gh-pages`, исходники остаются в `main`.

## Локальная демонстрация

Инструкция в README. Достаточно одного процесса Uvicorn, SQLite и собранного frontend. Сервис слушает только `127.0.0.1`. После демонстрации остановите его Ctrl+C. Он не требует OpenRouter, внешних API или платного хостинга.

## VPS после отдельного выбора хостинга

Подготовлен Docker Compose с PostgreSQL 16. Перед публикацией необходимо проверить реальный запуск на выбранном российском VPS, сменить пароль БД и обеспечить резервные копии на подходящей инфраструктуре. Сначала используйте SSH-туннель для закрытой демонстрации. Публичная эксплуатация без регистрации/защиты записи не входит в текущую версию.

Приложение за reverse proxy должно получать исходный Host (обычно `proxy_set_header Host $http_host` в Nginx). Middleware отклоняет браузерные записи с чужим Origin. Межсайтовые запросы не разрешены. Не публикуйте PostgreSQL в интернет, не используйте Cloudflare, не выставляйте текущий API без ограничения доступа. Перед публичным релизом добавьте TLS, аутентификацию оператора и rate limiting.

Миграции выполняются автоматически при старте. Для независимого запуска миграций из корня:

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
```

Данные существующей SQLite БД не мигрируют в PostgreSQL автоматически: потребуется отдельный перенос записей с сохранением ID, источников и дат. Alembic создаёт/обновляет схему, а не переносит содержимое между движками. При нескольких экземплярах приложения миграции следует вынести в отдельный однократный этап.

## SQLite: резервная копия

Из корня, допускается при работающем сервере:

```powershell
.\.venv\Scripts\python.exe scripts/backup_sqlite.py data/backups/catalog-backup.db
```

Скрипт использует SQLite backup API и отказывается перезаписывать существующий файл. Храните копии вне рабочего диска. Они включают общий каталог, **но не избранное, заметки и историю браузера**.

Восстановление: остановите приложение, проверьте выбранные абсолютные пути, сохраните текущую БД под новым именем, затем скопируйте резервную копию на её место:

```powershell
Move-Item -LiteralPath data/catalog.db -Destination data/catalog-before-restore.db
Copy-Item -LiteralPath data/backups/catalog-backup.db -Destination data/catalog.db
```

Эти команды предназначены для ручного выполнения оператором после проверки путей и отсутствия конфликтов имён. Перезапустите приложение, проверьте `/api/v1/health`, количество и карточки записей.

## PostgreSQL: резервная копия

Команда внутри контейнера создаёт файл, который затем копируется на хост; такой способ не повреждает бинарный архив из-за перенаправления PowerShell:

```powershell
docker compose exec -T db pg_dump -U suppliers -d suppliers -Fc -f /tmp/suppliers.dump
docker compose cp db:/tmp/suppliers.dump ./data/backups/suppliers.dump
```

Сначала создайте `data/backups`. Выбирайте уникальное имя для каждой копии.

Для пробного восстановления используйте **отдельную БД**, не рабочую:

```powershell
docker compose cp ./data/backups/suppliers.dump db:/tmp/restore.dump
docker compose exec -T db createdb -U suppliers suppliers_restore
docker compose exec -T db pg_restore -U suppliers -d suppliers_restore --no-owner /tmp/restore.dump
```

Проверьте содержимое восстановленной БД перед переключением connection URL. PostgreSQL backup/restore здесь задокументирован, но в текущем окружении без Docker daemon не выполнялся.

## Операторские действия

Для реальных записей в карточке доступна кнопка «Редактировать»: основные сведения, ассортимент, условия и документы. Каждое сохранение добавляет источник с новыми утверждениями и снимком предыдущих значений. Демо-записи не изменяются. Сохранение не означает независимую проверку фактов.

Без админ-панели доступны список и импорт JSON тем же валидируемым механизмом:

```powershell
.\.venv\Scripts\python.exe scripts/catalog_admin.py list
.\.venv\Scripts\python.exe scripts/catalog_admin.py import path/to/supplier.json
```

JSON соответствует телу `POST /api/v1/suppliers/import` в `/docs`. При конфликте исходное значение не перезаписывается произвольно; оба утверждения сохраняются в источниках. Для исправления выбранного значения используйте команду `correct` (см. `--help`), предварительно сделав резервную копию. Она сохраняет старое и новое значение в новом операторском источнике, не удаляет прежние источники и не назначает дату проверки автоматически.

Логи по умолчанию содержат HTTP-метод, путь и статус, но не тела запросов. Не включайте логирование тел с заметками или полными строками подключения. В production отслеживайте ошибки БД, свободное место и успешность резервного копирования.
