# Архитектура

Модульный монолит без ИИ и платных запросов. React 19 + TypeScript + Vite; FastAPI + Pydantic; SQLAlchemy 2 + Alembic; openpyxl. Сборка frontend раздаётся самим API. CSS и системные шрифты локальны, внешних CDN и Cloudflare нет.

## Данные

`suppliers` — общий каталог. Основные поля и индексируемые признаки реляционные. Товары, контакты, коммерческие условия, источники, документы и конфликты разделены в JSON-полях. Такой объём достаточен для прототипа; при росте их можно вынести в связанные таблицы следующими миграциями.

`is_demo` — обязательная граница: список, карточка, сравнение, коллекция избранного и экспорт ограничены выбранным режимом. Реальные и демонстрационные записи не объединяются при дедупликации. Демо идентифицируется и в содержимом выгрузок.

Поиск: нормализованный Unicode-текст с `casefold`, заменой ё/е и безопасными SQL-параметрами; все слова запроса обязательны. Ищет в названиях, описании, товарах, городе и категориях. Это не понимание естественного языка, не морфологический и не семантический поиск. Фильтры на «есть сведения» не утверждают истинность этих сведений. Сортировка по полноте соответствует доле восьми заполненных блоков; это не рейтинг надёжности поставщика.

Индекс данных вычисляется в `scoring.py`, не хранится как неизменяемая оценка в БД. Его версия и детализация возвращаются API и показываются в интерфейсе; методика в `rating.md`. Фильтры актуальности, индекса, цены и заказа применяются до пагинации; экспорт и коллекция избранного используют ту же функцию каталога. Диапазоны цены/заказа проверяются для одной записи условий, с учётом единицы и валюты. Подходящая позиция передаётся как `matched_term_index`, чтобы интерфейс и сравнение показывали её цену. Товары из коммерческих условий входят в поисковый ассортимент.

Производные фильтры и объяснимое ранжирование обрабатывают отобранные SQL кандидаты в Python. Это сознательное упрощение для ограниченного каталога прототипа, не решение для миллионов записей. Перед увеличением объёма нужны нормализованные таблицы условий, индексы и перенос подходящих операций в PostgreSQL.

SQLite служит для бесплатного локального запуска. Compose использует PostgreSQL через тот же слой доступа. В прототипе не реализованы PostgreSQL FTS, очередь задач или Redis. Поиск синхронный, поскольку внешних обращений нет; интерфейс получает загрузку/ошибку и не блокируется.

## Сохранение и происхождение

Ручной импорт требует названия, категории и URL источника. Он не скачивает страницу и не назначает `checked_at`. Текущие значения и исходные утверждения в `sources.claims` сохраняются отдельно. При повторном импорте сравниваются ИНН, затем официальный домен без www, затем нормализованное название с точным адресом. Разные ИНН и неоднозначное совпадение не объединяются. Конфликтующие значения остаются в источниках; интерфейс показывает статус перепроверки. Одни и те же утверждения с тем же URL не создают новую копию источника.

`PATCH /api/v1/suppliers/{id}` редактирует реальную карточку: прежний снимок полей записывается в новый источник вместе с новыми утверждениями. Demo-записи редактировать нельзя. Изменение ИНН/домена на принадлежащий другой карточке отклоняется с 409. Коммерческие условия и документы проходят валидацию; изменение не назначает дату проверки.

Импорт сериализован блокировкой в одном процессе, чтобы параллельные ручные добавления не создавали дубликаты. Локальный прототип запускается **с одним worker**. Для нескольких процессов нужны транзакционные блокировки/идентификационные ключи в PostgreSQL и тесты гонок.

Возраст проверки определяется по последнему `checked_at`. Отсутствие проверки — `unverified`; конфликт или проверка старше порога — `needs_review`. Факт нахождения сайта не подтверждает готовность к отгрузке. Дата получения не подменяет дату проверки.

## Персональные функции

Локальный модуль `local.ts` хранит избранное, заметки и историю в браузере. На сервере нет маршрутов избранного/заметок и общей пользовательской таблицы: это осознанное изменение по согласованному объёму первой версии. Коллекция избранного получает список ID и применяет те же серверные фильтры. Персональные заметки передаются только при явно выбранном экспорте.

## Следующие расширения

1. **Внешний поиск:** контракт в `providers.py`; сейчас активен только честный ответ `not_configured`. Реальный адаптер добавляется после проверки прав использования, доступности из целевого окружения и квот. Поисковые ссылки сначала рассматриваются как кандидаты, затем нормализуются и сохраняются в реальный каталог с источниками. Нельзя брать заголовок произвольной страницы за название юридического лица без идентификации.
2. **Получение страниц:** отдельный безопасный сетевой модуль с DNS/IP-проверкой каждого соединения и редиректа, запретом внутренних адресов, лимитами размера/времени и соблюдением правил источника. Сейчас никакие введённые URL сервером не запрашиваются, SSRF через форму отсутствует.
3. **ИИ:** отдельный парсер запроса с проверяемой схемой фильтров и отключением по конфигурации. Он не должен создавать компании или коммерческие факты. OpenRouter можно будет подключить здесь после отдельного согласования бюджета. Сейчас соответствующего клиента и ключей нет.
4. **Масштабирование:** PostgreSQL FTS/индексы, таблицы фактов/источников, асинхронные задания со статусами и жёсткими квотами; затем серверные аккаунты и организации. Микросервисы для этого не требуются.

Перед публичным запуском нужны авторизация/защита административных действий, ограничения частоты и нагрузки, TLS и применимые документы обработки данных. Нынешний HTTP API без авторизации предназначен только для локальной/закрытой демонстрации.


## Автономный адаптер для GitHub Pages

По последнему решению пользователя добавлена `npm run build:pages`. React-интерфейс сохраняется, `api.ts` выбирает браузерный адаптер из `standalone/` вместо FastAPI. Фикстура содержит только 12 явно учебных записей из отдельной временной БД. Реальные ручные записи сохраняются в localStorage отдельно от личных данных. Фильтры, дедупликация, источники/история, оценка и экспорт работают фактически в браузере. Это согласованное ограничение статической демонстрации, а не перенос критической логики публичного SaaS на клиент. Серверная сборка исключает браузерный движок и демофикстуру.

Браузерный XLSX — минимальный SpreadsheetML-пакет с ZIP через MIT-библиотеку fflate: только строковые ячейки, без формул и макросов, стили/ширины/фильтр/закрепление. CSV UTF-8 с BOM. Данные обоих форматов экранируются. Источник формата: [Microsoft, SpreadsheetML](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document).

[Подробности режима Pages](github-pages.md). Секретов `VITE_*` нет; подключения платных API отсутствуют. Для возвращения общего каталога используется серверный режим, перенос локальных данных — отдельный последующий инструмент.
