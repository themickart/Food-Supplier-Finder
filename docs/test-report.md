# Отчёт о готовности тестовой версии

Дата: 24 октября 2026 года. Текущий объём: демонстрационный прототип без ИИ, с нулевыми расходами на API и хостинг. Функции, ограничения и варианты запуска описаны в README и документации. Локальное проектное задание в публичный репозиторий не включается.

## Автоматические проверки

- **Pytest: 39 passed.** API, граница real/demo, фильтры на русском, доставка отдельно от расположения, происхождение данных, повторный импорт, разные ИНН на одном домене, URL/ввод, cross-origin записи, экспорт обоих форматов, формулы, пагинация, миграция, индекс/порог/сортировка, диапазоны с единицами/валютой, выбор подходящей товарной позиции, редактирование и история. Дополнительно проверены фильтр реально проверенных контактов, поиск по географии доставки и миграция существующего поискового индекса без изменения фактов.
- **Vitest: 24 passed.** Чтение/валидация личных данных и настроек, повреждённые/некорректные данные, диапазоны и единицы, сохранённые фильтры, отсутствие подмены неизвестной цены нулём. Калькулятор (единицы, валюта, минимум, округление, неполные/невалидные данные), автономный каталог (дедупликация/конфликты/история/сохранение/ошибки), согласованность индекса и полноты с серверным снимком, ZIP/XML XLSX и защита формул.
- **Playwright, серверная сборка: 22 passed, 4 skipped.** Одиннадцать сценариев × desktop/mobile Chromium. Пропущены только четыре проверки автономного каталога. Проверены прежние сценарии, колесо над таблицей, положение панели выбранных записей при прокрутке и возврате, порядок видов, калькулятор и переключение нового/старого бренда.
- **Playwright, Pages-сборка: 24 passed, 2 skipped.** Двенадцать сценариев × desktop/mobile Chromium. Проверки личных функций, фильтров, сравнения и экспорта выполнены повторно для браузерного адаптера. Дополнительно проверены добавление/правка/перезагрузка/история, изоляция профилей, отказ localStorage, отсутствие обращений к `/api`. Две проверки отказа backend пропущены: backend в этой сборке отсутствует.
- **TypeScript + Vite build: успешно.** Включены строгая типизация и проверка неиспользуемых переменных. Обычная сборка: основной JS 346 КБ / 101 КБ gzip. Pages: основной JS 344 КБ / 100 КБ gzip, отдельно браузерный адаптер 62 КБ / 10 КБ gzip, экспорт 15 КБ / 7 КБ gzip. Обе сборки успешны.
- **Ruff: lint и format check прошли.** В Pytest остаётся одно предупреждение об устаревающем httpx-интерфейсе TestClient в установленной Starlette; функциональные тесты проходят.
- **Docker Compose: `config --quiet` прошёл.** Это проверка конфигурации, не сборка и не запуск контейнеров.

Браузерные тесты выполнялись на отдельной SQLite БД `artifacts/e2e.db`. Созданные ими вымышленные «реальные» записи не попадают в рабочую БД `data/catalog.db`. Внешние API не вызывались; тестовые фикстуры не являются найденными поставщиками.

## Проверка перед публикацией репозитория и Pages

После настройки исключений повторно выполнены 24 модульных теста, сборка Pages и 24 браузерные проверки автономного режима (две проверки backend пропущены по назначению). `scripts/check-publication.mjs` проверил 90 файлов репозитория, 24 примера исключений и 6 статических файлов Pages. В публичном списке нет локального задания, его внутренней сверки, пользовательской БД, выгрузок, ключей и зависимостей. Относительные ссылки документации и соответствие package-lock манифесту проверены.

Отрицательная проверка: временный синтетический `Task.md` внутри Pages-артефакта был отклонён проверкой публикации, затем удалён. Исходное локальное задание не изменялось. Workflow повторяет проверки перед загрузкой артефакта. Эти измерения выполнены локально перед первой публикацией; состояние удалённых проверок отображается в GitHub Actions.

## Локальная производительность

`scripts/benchmark_catalog.py`: отдельная временная SQLite БД, 10 000 синтетических компаний, 10 последовательных запусков поиска «Моцарелла» с категорией и городом, подсчёт количества и возврат страницы из 12 результатов.

- Медиана: **236,00 мс**.
- Максимум: **268,09 мс**.
- Условия: один процесс на текущем компьютере; измерен слой каталога с сериализацией результатов, без HTTP/браузера.

Это проверка ориентировочной скорости на синтетическом наборе, а не обещание задержки на VPS или при параллельной нагрузке. PostgreSQL Full Text Search пока не реализован.

После добавления объяснимого соответствия и производных фильтров поиск обрабатывает SQL-кандидатов в Python. Новый замер отражает эту логику и заменяет первоначальные измерения простой версии. Результат укладывается в ориентир 1 секунда на этом синтетическом наборе; для роста объёма обработку условий следует перенести в индексированные таблицы PostgreSQL.

## Резервное копирование

На отдельной тестовой SQLite БД выполнены `scripts/backup_sqlite.py`, восстановление в другой файл и `PRAGMA integrity_check`: **ok**, количество записей сохранено. Рабочая БД не заменялась. Процедуры PostgreSQL приведены в документации, но фактически не выполнялись.

## Невыполненные критерии полного MVP

1. **Реальный автоматический внешний поиск:** провайдер и ключ не подключены; есть документальная проверка кандидатов, нет воспроизводимо подключённого источника и полевого отчёта по целевым категориям/регионам. В дополнительном Overpass-spike получен один реальный HTTP 200 за 28,56 с (3 объекта), затем два ReadTimeout (18,42/15,55 с); устойчивость и CORS для Pages не подтверждены. Реальные данные не импортировались в приложение. [Подробности](data-sources.md). Ручное добавление и демо не засчитываются за внешний поиск.
2. **Автоматический сбор/обогащение сайтов:** отсутствует. Введённые URL не скачиваются сервером. Контакты и коммерческие факты не объявляются проверенными автоматически.
3. **ИИ:** исключён пользователем из текущей версии. Нет интерпретации свободной речи моделью или ИИ-ранжирования; проверять «ошибку ИИ» пока неприменимо. Обычный каталог от ИИ не зависит.
4. **PostgreSQL/Docker/VPS:** подготовлены схема/Compose/инструкции, но Docker daemon в текущем окружении не запущен. Не проведены сборка контейнера, runtime-тесты PostgreSQL, установка и проверка на российском VPS.
5. **GitHub Pages:** автономная сборка и ручной workflow подготовлены, локально проверены. Публикация выполняется из ветки `gh-pages`; исходники находятся в `main`. Доступность из целевой сети проверяется отдельно от локальных тестов. На Pages каталог хранится в браузере, это не выполнение требования общей серверной БД.
6. **Публичный многопользовательский сервис:** вне согласованного объёма. Нет регистрации, ролей, защиты записей серверной авторизацией и синхронизации персональных данных. Доступ только для локальной/закрытой демонстрации.
7. **Расширенное управление данными:** полноценной админ-панели и автоматической верификации нет. Редактирование карточек, условий и документов доступно в интерфейсе; CLI оператора также сохранён. Рейтинг надёжности не создаётся без сведений о фактической работе поставщика.

Проект готов к демонстрации функционала **как прототип**, но не объявляется завершённым исходным MVP. Для дальнейшего развития не требуется оплачивать ИИ сейчас: сначала можно выбрать допустимый бесплатный поисковый источник и проверить реальные результаты, затем отдельно согласовать платные проверки или ИИ.


Текущие скриншоты для локального просмотра находятся в игнорируемом `artifacts/`: каталог, мобильный экран, калькулятор позиции и закреплённая панель. Проектное задание и его подробная внутренняя сверка остаются локальными.
